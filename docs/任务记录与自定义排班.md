# 任务记录与自定义排班

## 使用

- 二级保电无 T−1，起始日强制人工巡视并正常测温；后续日期按原设备配置判断。
- 自定义模式依次填写项目名称、单日巡视日期、巡视次数（1/2/3，默认 1）、测温次数（0/1/2/3，默认 0）、保电设备。每个识别到的变电站只生成所选日期的一条人工巡视记录，次数原样采用表单值。项目名称直接用作任务名称，不参与 T−1、间隔频次、长周期替代或测温豁免计算。
- 自定义草稿可逐行编辑巡视方式、巡视次数和测温次数。机器选项仍按本站设备资格显示；切换方式不会重算手动输入的次数。单行保存后确认生效，最终值保存在每日明细中，任务表头保留录入时的默认配置。
- 首页“排班任务记录”可查看整个任务、导出可打印 Excel、编辑任务参数。编辑后重新生成草稿，核验确认才替换原任务。关闭表单或草稿不会修改已保存的数据。
- 任务列表“删除”需原生确认，按 `taskId` 在同一事务中删除表头与全部每日明细；失败整体回滚，成功后立即移除列表项并刷新日历计数。零明细任务也可删除，不影响其他任务。
- 编辑会重新计算整个任务，其旧明细中的手动调整、手动删除不自动保留。

## 存储和升级

IndexedDB `substation-schedule` 使用版本 2：`tasks` 表以 `taskId` 为主键；`plans` 使用同名索引作为任务外键。任务表保存类型、级别、项目名、通知单号、原始设备文本、站名、起止日期，以及时间和修订版本。自定义表头额外保存单日 `inspectionDate`、`inspectionCount`、`temperatureCount`，且 `startDate`、`endDate` 均为该单日，不再保存多选日期。

确认任务时，表头与明细在同一事务中写入。编辑保留原 `taskId`，同一事务内替换其全部旧明细；写入失败整体回滚。任务在打开后若被其他操作修改或删除了明细，将拒绝过期编辑，要求重新打开任务。

旧版只有每日明细，无法精确恢复每次填表的边界。升级按原有类型、级别、项目名、单号与设备文本归档任务，保留每条原始记录及 ID；日期、站点和设备由现存记录推导，并标记“历史归档”。旧任务首次编辑需要人工核对回填信息。

## 离线备份

新版 JSON 格式为 `{ format: 'substation-schedule', version: 2, tasks: [...], plans: [...] }`，同时保存任务表头和明细。导入前检查外键关系，导入后可继续编辑自定义日期和次数。

原有多日自定义任务及备份继续保留所有明细，可查看和导出。编辑时回填最早日期及首条明细的次数，并明确提示：重新保存会替换原任务全部明细，仅保留新选择的单日配置。不会在读取或导入时静默丢弃其他日期。

覆盖导入原子替换两张表。合并新版备份按 `taskId` 整组新增，已存在的任务保留本机版本，避免旧备份复活已删除的明细或覆盖人工修改。需要完全使用另一台电脑的版本时选择覆盖导入。

仍兼容旧版 JSON 数组：覆盖时归档任务；合并按原有业务字段去重并归档新增记录。空数组 `[]` 覆盖导入会清空任务和明细。旧版程序不支持新版任务备份，交换新版备份时应统一使用更新后的程序。
